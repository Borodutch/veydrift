# Ceremony manifest authenticity (inactive integration API)

This standalone stdlib-only package authenticates named Ed25519 signers over a bounded manifest. It does not replace runtime/catalog.go approvals, load artifacts, decode native gnark input, run setup or enable activation. It is reusable repository code, not a fixture-only script; no existing consumer is wired to it yet.

## Owner trust policy

Owner decision Telegram22700 / board1914 accepts **single-operator trust**. External independent secret contributors are not a required production gate under that decision. Code review remains independent; cryptographic verification, audited source/circuit/child-key binding, no-toxic-waste procedure, proof/EVM/full-coverage evidence and release gates remain required. Earlier pilot/intake reports are historical and not rewritten.

Use TrustMode=single-operator with one externally configured OperatorID, exactly one matching public signer with role operator, threshold1 and RequiredRoles[operator]=1. All contribution records name that same operator; repeat contributions are allowed but cannot masquerade as separate people. Different strings/keys never prove human independence. No disjoint approver/contributor requirement is imposed. development stays a separate mode; independent-claim is optional metadata, not a requirement or proven property.

Tests use public fixed deterministic DEV signing seeds, including a clearly synthetic single-operator-mode mechanics test. They create no operational credentials, ceremony entropy, production approval or real identity attestation. Production registry is absent; missing trust fails unapproved. Registry provenance/secure distribution is a caller responsibility: never construct Trust from bundle fields or install test keys as production trust.

## Wire and API

1. Freeze Manifest metadata: exact source, dependency/go.sum/build manifest and rules digests; per-node circuit/schema and CCS/PK/VK byte counts+digests; ordered child IDs/VK hashes; ordered per-phase contribution artifact digests/identities and beacon policy/value/evidence digests. Children must precede parents. These statements bind signed metadata, not actual circuit semantics or transcript validity. Phase1 may be repeated across nodes; aggregate bounds count repeated references conservatively.
2. Encode structs with encoding/json.Marshal (exported Go field names, field order, no omitted fields or whitespace). Envelope.Payload and Signature.Signature use Go JSON base64 encoding of byte slices. Exact re-marshalling rejects unknown/duplicate/omitted fields and alternative encodings. Empty Children must be [] not null.
3. SigningBytes(payload) validates metadata and returns exact Domain UTF-8 || zero byte || uint64 big-endian payload byte length || original canonical payload bytes. Domain is veydrift/ceremony-manifest/ed25519/v1. Sign externally. Envelope.Domain must match too. Package has no signing or private-key generation API.
4. Caller obtains trusted PUBLIC signer registry, revocation flags, policy ID/scope/role thresholds and Binding externally. Binding includes exact payload SHA256 plus source/dependency/rules SHA256. Never infer expected pins from an attacker-controlled bundle. Verify(rawEnvelope, trustedRegistry, expectedBinding) rechecks all policy/revocation state per call; every supplied signature must be valid/known/nonrevoked/unique, even if threshold already met. Duplicate registry IDs or public keys reject. Role thresholds apply to distinct signer IDs, with one role per signer.
5. Successful Result.Authentic means only these named keys signed exactly these pinned bytes under caller policy. OperatorIndependenceVerified, CryptographicTranscriptsVerified and ProductionReady ALWAYS remain false. Failure wraps ErrUnapproved and returns zero Result. Caller must not treat returned structs as unforgeable capabilities.
6. RequireNativeDecode ALWAYS returns ErrNativeDecodeBlocked. This is an explicit fail-closed API barrier for future integration, not an interception of other code. No native parser is imported or called. Structural bounds/sandboxing for novel gnark transcripts, actual same-byte artifact hashing, full contribution checks, deterministic key extraction and source/parent-constant validation remain separate work. Existing tiny verifier can only verify its compiled DEV allowlist; it is not silently generalized here.

Limits:64KiB payload,128KiB envelope,16 nodes/signers/children,64 total transcript records,64MiB declared individual artifact and256MiB total declared bytes. These preparation limits are not production capacity claims. JSON parsing allocation is bounded by input bytes; semantic collection counts are checked after bounded JSON decode. Callers bound transport reads before creating raw []byte and keep raw/trust/binding immutable during Verify. No remote input, filesystem access, native decoding or artifact allocation occurs here.

No expiration or automatic revocation feed exists; caller must supply current trusted registry/policy each call and explicitly pin desired manifest to prevent old-manifest replay. No deployment identity, full graph policy or native artifact loader has been activated. Parent coordinator owns operational trust registration, procedure and release decisions.

Run: go test -count=1 -timeout=30s ./ceremony and go vet ./ceremony from packages/battle-prover. No external modules are imported by this package.
