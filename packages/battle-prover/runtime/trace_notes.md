# Native trace driver integration

API (implemented in trace.go): `NewTrace(snapshot, approvedRelease, WitnessLimits) (*Trace,error)`, `Next(ctx) (*TraceEvent,error)` (io.EOF at completion), `Chunk(ctx,budget) ([]TraceEvent,error)`, `Checkpoint() (TraceCheckpoint,error)`, `RestoreTrace(snapshot,release,limits,checkpoint)`, `Replay(ctx,budget) (bool,error)`, `Result() (*TraceResult,error)`. Phase IDs match composition; qualification uses TraceQualification=7 and emits one LinkedCircuit. Group is decimal cohort for attribution and bridge Close, empty otherwise. Each event contains Phase, Group, Kind and Step frontend.Circuit. Endpoints are `map[int]TraceEndpoint`; attribution endpoints are separately keyed by group. Each endpoint contains First/Last circuits and uint256 Count. Result contains qualification, output Manifest/Leaves and Close association.

Native API gaps found: resultbridge.Next(Close) runs an unbounded nested attribution loop; report only exposes bulk ReportWitnesses; raw only exposes bulk Build; combat.New materializes roster/RF and output.FromBridge builds a suffix chain. Runtime uses public typed adapters for Close and report, stepping actual attr.Machine per Next (no hidden nested execution), raw Build only during explicit constructor admission. Combat construction remains O(expanded roster*tree depth) at phase boundary; output initialization O(member count). Those materializations are not circuit transitions; cancellation is checked before them. No fixture step budget or roster hardcoding. Host storage is finite and not an arbitrary-size chain guarantee. attr.Prepare also scans/sorts the current materialized cohort at its boundary; it does not run attribution transitions. Admission is limited by WitnessLimits document/row budgets; no full-trace transition ceiling is imposed. Counts are uint256, individual chain row quantities are ABI uint32. Next emits at most one elementary relation, Chunk/Replay emit/replay at most the requested count. These are transition budgets, not wall-clock or per-allocation memory limits; process-level resource enforcement remains mandatory.

Checkpoint is replay advice, never proof authority. Restoring revalidates authoritative snapshot/release and replays every native transition with a caller-supplied bounded event budget, then checks event transcript digest and cursor before allowing new work. Callers must independently resume/rebuild elementary proof prefixes. Raw steps are emitted first, followed by preparation, one qualification event, combat, bridge with interleaved attribution before each Close, report and output. Attribution has a separate chain per Group: do not merge different groups. Pass ordinary Step values to composition.NewLeafWitness; use composition.NewCloseWitness for bridge Close after reducing that Group's complete attribution proof, and handle qualification with its dedicated adapter. No proof APIs or Go test subprocess are called by this driver.
