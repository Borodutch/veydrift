# Durable verified frontier

## Stable integration API

- `FamilyReceipt{ID composition.FamilyID, First,Last [10]string, Count [4]uint64, Native NativeReceipt}`: canonical decimal BN254 endpoints, little-endian uint256 count. `NewFamilyReceipt(id,range,native)` copies bytes; `Marshal()` / `ParseFamilyReceipt(data)` enforce canonical JSON. Parsing does not imply verification.
- `VerifyFamilyReceipt(ctx,catalog,receipt) (composition.FamilyEnvelope,error)` loads only independently approved catalog VK bytes, checked/canonical-decodes proof and exact three-public witness, matches range commitments, runs actual Groth16 verification with recursion-native options, reconstructs `CatalogAuth` using ValueOfProof/Witness/VerifyingKeyFixed. No receipt-selected VK trust.
- `FrontierBinding{Identity service.Identity, Anchor service.Anchor, Phase int, Group string, SourceSHA256 string}` binds one deterministic source group. Group is a canonical decimal uint256. SourceSHA256 pins the exact replayable group description.
- `NewFrontier(catalog *Catalog,binding FrontierBinding) (*Frontier,error)`; configured root height comes from the approved catalog, not input or checkpoint.
- `RestoreFrontier(ctx,catalog,binding,checkpoint []byte) (*Frontier,error)` independently compares binding, validates cursor/interval coverage and legal slots, and cryptographically verifies EVERY stored receipt before returning.
- `PushLeaf(ctx,cursor [4]uint64,receipt FamilyReceipt) error` accepts a verified elementary receipt at exact next `Cursor()`, increments uint256 cursor, performs no proving. Drain pending Advance operations before pushing another leaf.
- `Advance(ctx) (worked bool,err error)` executes AT MOST ONE real ProveApproved operation and authenticates its result before committing the transition. Error leaves state unchanged. Pending D0, binary B_h, dispatch D_h and unary promotion are inferred from the authenticated rightmost intervals, not an attacker-editable instruction.
- `Finish() error` seals nonempty input, without proving. Continue one-step Advance until `Root() (FamilyReceipt,bool)` yields D at the catalog root height. Root does not mean phase completeness: designated adapters/Close enforce that relation.
- `Checkpoint() ([]byte,error)` emits canonical versioned public JSON. `Segments() []FrontierSegment` exposes ordered intervals (`Start [4]uint64, Receipt FamilyReceipt`) as defensive copies; `Cursor() [4]uint64` is the next input index.

## Engine obligations / exact boundary

The engine must replay deterministic source before using a restored checkpoint, checking EVERY segment's Start, Count, First and Last against the exact source range, leaf kind for raw pending leaves, and source exhaustion before Finish/root use. This is required: a genuine proof under the same catalog does not itself bind service metadata, and a JSON binding is not an authenticated source oracle. Do not trust a saved Finishing bit as proof that the source ended. Cursor equals contiguous verified work; no numeric truncation or host count-only authentication is used.

Call Checkpoint after each accepted leaf, Finish, and successful Advance; atomically persist via the existing fenced service store before committing associated engine cursor progress. On crash before persistence, the previous checkpoint may recompute the same proof operation, but never incorporates that leaf twice. Store fencing handles stale-checkpoint rollback; frontier serialization alone cannot prevent replacing the entire checkpoint with an older valid one. No file writes/fsync/lease ownership are hidden in this API.

Production constructors install ONLY the concrete Catalog and ProveApproved implementation. Compile/setup/dev-key promotion are absent. Bridge Close acceptance requires a real approved CompleteClose receipt constructed by the engine using the separately verified attribution D_root. Run inside the killable processrunner resource boundary: context is checked before/after but gnark proving itself is not cancellable. The one-proof Advance boundary prevents a hidden 256-proof promotion burst.

Memory is O(height) receipts (at most height+2); checkpoint limit 32 MiB, per proof at most 64 KiB, public witness exactly 108 bytes. Untrusted proof allocation headers and compressed-point offsets are checked BEFORE ReadFrom. Approved VK decoding is hash-first and still belongs inside OS resource limits. Keys are not retained across calls. Only configured heights backed by the full seven-phase approved catalog DAG are supported; height 256 is a capacity/configuration capability, not a claim that D256 proofs were generated here.

## Validation

`GOMAXPROCS=2 GOMEMLIMIT=2GiB go test ./runtime -run TestFrontier -count=1 -timeout=5m` passed in 1.982s. The complete runtime suite also passed in 30.667s under the same CPU/memory/timeout settings. Frozen real raw-phase development proofs are trusted ONLY by explicit _test.go key pins; no setup/heavy proof generation. The seven-leaf path executes 20 independently verified proof-result steps (D0/B/D including unary promotion), serializes/restores at 28 boundaries, and checks exactly one proof operation per Advance. Negative tests alter proof/public bytes, native allocation headers, point encoding, scalars/padding/count, key/catalog, source/group/identity/anchor, cursor/offset/order/omission, and both prefix/pending proofs. Also checks cancellation/failure atomicity, defensive copies, uint256 boundaries, and the public RestoreFrontier/concrete catalog VK-loading path with explicitly test-only trust. Structural uint256 tests are labeled non-cryptographic and make no high-root proof claim.
