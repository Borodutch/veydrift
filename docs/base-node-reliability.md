## Proven relay defects and versioned replacement

[scripts/base-node/l1-rpc-failover.py](../scripts/base-node/l1-rpc-failover.py) preserves the deployed filename, port, health endpoint and three environment variables. It is a proposed reviewed replacement, not a new unrelated proxy. The previous implementation retried cooling providers, rotated after HTTP429, used unbounded request threads and lacked whole-response deadlines, chain/hash fallback checks and response ID/shape validation. A valid 8,500,398-byte receipt payload exceeded the old 8MiB ceiling in incident #58; that incident already raised the live ceiling to 16MiB. This change keeps the existing 16MiB budget rather than repeatedly increasing it.

The replacement streams in 64KiB chunks to a hard cap before JSON decoding, rejects oversized declared bodies, compressions and malformed responses, bounds request bodies to 1MiB and batches to 100, and serializes upstream work behind four admitted HTTP handlers and an eight-socket listen backlog. Python JSON object expansion is not an exact byte-for-byte memory bound: retain a container memory ceiling (recommended 512MiB after representative receipt measurement) in addition to the wire limit. One active response parse, bounded learned identities and bounded admitted requests prevent traffic-dependent unbounded retention. Operators should alert on memory/PSI rather than assume the body budget equals resident size.

A single relay call has a 12-second total upstream/lock budget. A wall-clock shutdown retains the actual upstream socket before HTTPConnection can detach it, interrupting slow body, chunk-size and trailer trickles even with Connection: close; a request handler has a 24-second total bound. Connection establishment uses socket timeout; OS DNS resolution may exceed Python socket timeouts, so container/process supervision remains a residual bound. No autonomous restart is introduced. Failure cooldown doubles from 10 to 300 seconds. Cooling providers are never attempted. HTTP429/known RPC rate-limit codes hold ALL upstream access for at least Retry-After (60-second minimum), without rotation to evade quota.

The configured first provider is trusted after Ethereum chain ID and finalized anchor validation. Fallback is failure-only and sticky; it checks the original finalized anchor at the same height and validates all retained recently learned hashes against canonical same-height blocks (at most 256 identities). All checks share the request time budget, so a large proof can safely fail closed rather than exceed it. This strict design may reduce availability after a genuine L1 reorg, and it does not implement quorum consensus or cryptographically prove an entire ancestry chain. Unknown earlier history and restart-lost recent cache remain limitations; restarting is NOT a way to clear disagreement. Only enable a fallback after workload/canonical tests below. The existing ONE provider remains unchanged by default. Credentials never appear in health/errors; redirects are not followed.

The method allowlist is read-only and includes the current execution derivation calls. A newly introduced node RPC method will fail closed and must be reviewed explicitly. It does not proxy WS, beacon or sends. L2 backend HTTP/WS requirements are a separate compatibility gate, not proof supplied by an L1 relay test.

## Normal next-L1 block absence

Official node v1.4.2 (revision 5034ef80bc90261ff6c4841fdf4baed34283abad) polling traversal asks for origin.number + 1. Its chain provider treats number-based block-not-found as temporary, whereas hash-based not-found requests a reset. A normal not-yet-produced numeric block therefore must remain JSON-RPC result:null, not become a relay HTTP503 and cross-request provider cooldown.

The relay permits this only for numeric eth_getBlockByNumber nulls above both a fresh same-provider latest block and all known height evidence. It validates every sibling first, independent of request/response ordering; finalized anchor, retained learned identities, successful block/eth_blockNumber responses and a monotonic observed-height scalar all rule out historical absence. The scalar survives learned-cache eviction (not process restart). A regressed latest proof fails closed. Before granting an exemption, its hash must also match EVERY available same-height identity from the established/candidate anchor, retained learned cache and validated block siblings, regardless of either batch order; matching heights alone cannot hide an explicit fork contradiction. Missing historical blocks, hash/tag nulls and required-data application errors keep their existing failure behavior. Allowed nulls bypass block validation/cache insertion and introduce no failure, cooldown or fallback; subsequent ordinary calls remain usable.

Each otherwise-eligible response/batch adds at most ONE latest read with a 1MiB body cap under the original deadline, never another provider or a recursive proof. Numeric null classification stores at most 100 candidate numbers, 358 temporary identity pairs (256 learned, two anchors, 100 siblings), plus one retained scalar, not an unbounded history. The original response remains resident during this bounded proof. HTTP429 and known RPC quota errors in either the original response or proof hold all upstream access; batch quota scanning still precedes every sibling. This is same-provider consistency evidence, not independent consensus or cryptographic proof: a provider lying consistently about unseen history is outside this relay's trust model. A head advancing between null and proof may conservatively fail closed rather than bless an ambiguous missing block.

Full loopback HTTP regressions in scripts/base-node/test_future_blocks.py cover next-L1 null → unrelated receipt/chain success → normal learning after head advance, false future claims, fresh proof per call, evicted history, unordered same-height siblings, a 100-request mixed batch, required hash/tag/data nulls, batch/proof quota dominance, and proof size/deadline bounds. No production probes, faults, configuration changes or restarts are part of this implementation.

## Deterministic observation, targets and escalation

[health.py](../scripts/base-node/health.py) is a one-shot sampler for integration into the existing owner, not a scheduler. Supply BASE_LOCAL_RPC, BASE_REFERENCE_RPC and BASE_REFERENCE_RPC_2 through approved environment resolution; never put secret URLs in arguments or output. It checks Base chain ID, latest/safe/finalized ordering, each timestamp and same-height canonical identities on two references, with three head probes and two identity probes of six seconds each (30 seconds maximum excluding OS DNS). Read-only outputs distinguish local lag, whole-network lag, reference disagreement and unavailable probes. Independent corroboration is not a consensus quorum. Configure genuinely independent references, not two aliases of one provider.

Targets: latest <=120 seconds old and <=60 blocks behind references; safe local lag <=900 blocks; finalized local lag <=900 blocks. An absolute safe/finalized age above 1800/2100 seconds with references equally stale is network-wide lag, not permission to restart the local node. These are alerting targets, not consensus guarantees. Require three consecutive unhealthy observations, then one actionable incident notification; reminder cooldown is one hour. transition() returns proposed state and alert intent; the existing messaging owner must acknowledge notifiedStatus/notifiedAt ONLY after successful delivery and atomically persist its bounded state. A recovery notification also requires delivery acknowledgment. No duplicate heartbeat or model polling is needed.

Collect at least two finalized advances after the final change with no subsequent reset and sustain a bounded observation window. Healthy latest/eth_syncing=false alone cannot clear derivation stalls. Recovery is diagnostic/manual: no restart storm, automatic failover on lag alone, data reset, or chain wipe. Escalate disagreement, repeated timeouts, sustained local finality gap, chain disk >=80%, anonymous execution memory >=85%, PSI avg10 >=10%, or recurring resets to the existing incident owner. Backend queue-age, funds, retained-count and ambiguity alerts are additional app-owned gates.

## Independent-review corrections

Ordinary validated JSON-RPC application/capability errors (including method-not-found, invalid parameters and call revert) are forwarded as HTTP200 with original code/id and a fixed message, without provider cooldown or fallback. Internal errors (-32603) and resource-unavailable errors (-32002) trigger bounded provider cooldown and the same coherent sticky fallback as transport failures. Required-data methods also treat resource-not-found (-32001), and recognized -32000 missing-block/header/historical-state errors, as provider failures. Other -32000 application errors remain passthrough; provider-specific error wording is not an exhaustive taxonomy. Arbitrary upstream message/data and unknown envelope extensions are removed; successful result payloads remain protocol data, not sanitized public telemetry. Rate-limit envelopes are scanned across the entire response batch before sibling validation, so reverse ordering or malformed siblings cannot hide a quota hold.

The absolute ingress timer starts in handler setup, before request-line/header parsing, and remains through response completion. Regression tests exercise four simultaneous request-line and header trickles and require slot release followed by successful normal traffic.

Receipt collections must contain ordered unique transactions, consistent block hash/number, valid gas/status/bloom and logs with matching receipt/transaction identities. Hash requests bind directly; numeric requests additionally bind retained learned identity when unambiguous. Empty receipt arrays are valid; tag responses must be internally coherent but no pinned-tag claim is made. Raw header/receipt results require hex-string/list shapes. These checks do not recompute trie roots or decode raw RLP; execution remains the consensus verifier. The >8MiB fixture now consists of 3,500 structurally realistic logs, not a giant arbitrary string.

Every local/reference head timestamp is parsed. Canonical and reference disagreement take priority over lag attribution. Whole-network lag requires both references independently stale; within the tag height-gap tolerance (60 latest, 900 safe/finalized), no over-age head can become observed in the 61–900-block gap. Beyond that tolerance, corroborated reference leads remain local-lag. A stale local head with any fresh reference timestamp is local-staleness inside the height-gap tolerance. Boundary fixtures at 60/61/100/900/901 blocks prevent false recovery notifications. Full HTTP sampler tests use ordered heads and same-height canonical lookups. No new live reliability claim follows from these offline corrections.
